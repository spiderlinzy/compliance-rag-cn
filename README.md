# 可信金融合规问答器（最小可验证 RAG）

一个命令行单轮问答工具：只基于指定的 4 份文档回答金融合规问题，**每一条事实都能追溯到具体来源，检索不到就拒答**，并按材料的信任层级（FTH）输出置信度。重点不是回答得多漂亮，而是**不编造、可核查、能审计**。

本项目是《AI Compliance Engineering》的配套实践小程序，用最小的代码把书中最抽象的信任分层与 RAG 安全机制真正跑起来。

## 为什么需要它

金融行业对留痕和合规有极高要求：任何结论都要能回答"这句话的依据从哪来"。普通聊天式问答对幻觉、错误引用的容忍度较高，但在金融合规场景里，一条无来源、被错误演绎的陈述可能直接导致合规事故。

这个系统用一条可验证的信任链来解决问题：

- **检索不到就拒答**，不假装知道；
- **强制引用**，每条事实都锚定到具体片段编号；
- **独立验证器**作为第二道独立环节，专门核查引用真伪和语义一致性；
- **分层置信度**，置信度由材料自身的信任层级决定，不由模型主观打分。

## 核心特性

- **两道拒答防线**：检索层硬拦截（词面零命中、零成本）+ 模型语义可答性判断（词面沾边但无答案）。
- **强制引用锚定**：模型输出结构化 JSON，每条陈述带 `citation_id`，不允许无来源陈述。
- **独立引用验证器**：先做结构核查（引用 ID 是否真实存在），再做语义核查（原文是否支撑该陈述），与生成器是两次独立调用，形成权力制衡。
- **受控术语表**：把"虹膜、指纹属于生物识别"这类定义性、无争议的归类显式写成可审计的白名单，让系统能回答具体例子，又不靠模型的隐性常识硬推。
- **FTH 分层置信度**：按来源层级标注，同一结论取最高、不同结论取最低，保证不超过材料的信任级。
- **本地 BM25 检索**：不依赖 embedding 接口即可运行，检索模块可整体替换为向量检索而不影响其他环节。

## 验收效果

基于 14 道测试题（9 道知识库内、5 道知识库外）的真实评估，结果存于 `tests/eval_report.json`：

| 指标 | 结果 | 目标 |
|---|---|---|
| 无来源陈述数 | **0** | 0 |
| 引用准确率 | **1.000**（21/21） | ≥ 0.90 |
| 文档外问题拒答率 | **1.000** | ≥ 0.95 |

知识库外的问题（如"今天 A 股收在多少点""红烧肉怎么做"）都会被干净地拒答，而不是硬编一个答案。

## 快速开始

环境要求：Python 3.10 及以上。

1. 安装依赖：

   ```bash
   pip install -r requirements.txt
   ```

2. 准备密钥：默认使用火山方舟，也兼容 DeepSeek、通义等 OpenAI 兼容接口。用网页界面时，**直接在页面顶部的密码框粘贴 API Key 即可，密钥只在本次提问时于内存中使用，不会保存或写入文件，也无需配置 `.env`**。只有用命令行（cli.py）时，才需要把 `.env.example` 复制为 `.env` 并填入 key；密钥不要写进代码或提交到仓库。

3. （可选）重新抓取并清洗知识库材料：

   ```bash
   python build_docs.py
   ```

4. 启动问答，两种界面任选：

   - 网页界面（推荐，适合演示）：

     ```bash
     python app.py
     ```

     浏览器会自动打开本地页面，只在本机运行，不部署公网，密钥不离开这台电脑。

   - 命令行界面：

     ```bash
     python cli.py
     ```

5. 跑批量验收：

   ```bash
   python eval.py
   ```

## 目录结构

```
compliance-rag/
├── build_docs.py      # 一次性网页抓取与清洗，生成 docs 下的 md
├── config.py          # 模型连接、FTH 信任层级、检索全局参数
├── corpus.py          # 加载 md，切分为 231 个自包含 Chunk
├── retriever.py       # jieba + BM25 检索与硬拦截
├── generator.py       # 带引用的 RAG 生成（语义判断 + 结构化 JSON）
├── verifier.py        # 独立引用验证器（核心）
├── glossary.py        # 受控术语表（定义性归类的白名单）
├── cli.py             # 命令行入口，串联整条链
├── app.py             # 本地 Gradio 网页界面（演示用）
├── demo_guide.md      # 14 个演示问题各自演示什么（面试讲解脚本）
├── eval.py            # 批量评估并产出验收报告
├── docs/              # 4 份知识库材料（L1 法律 … L4 问答）
└── tests/             # 测试题集与验收报告
```

想深入了解每个模块的开发逻辑、数据流和设计取舍，见 [DESIGN.md](DESIGN.md)；机制与书籍章节的对应关系见 [chapter-mapping.md](chapter-mapping.md)；网页上 14 个演示问题各自对应什么机制，见 [demo_guide.md](demo_guide.md)。
